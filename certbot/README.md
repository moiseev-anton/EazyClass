# Обновление сертификатов и логов

В существующей production-установке после обновления файлов проекта:

```bash
cd /путь/к/EazyClassProject
bash certbot/install_renewal.sh
sudo cat /etc/cron.d/eazyclass-certbot
sudo logrotate --debug /etc/logrotate.d/eazyclass-certbot
```

Установщик читает TLS_CRON_SCHEDULE из certbot/.env и **перезаписывает** тот же
файл /etc/cron.d/eazyclass-certbot. Удалять старую задачу или добавлять её через
crontab -e не нужно. Системный cron подхватит изменение автоматически; служба
cron должна быть установлена и запущена. Установщик не запускает certbot,
не получает сертификаты и не перезапускает nginx. Нужен sudo для двух файлов
в /etc. Если ранее задача была вручную продублирована в другом crontab, такую
копию нужно убрать отдельно. Старые правила logrotate для этого же файла также
следует проверить: один файл не должен иметь два правила ротации.

`logrotate --debug` только проверяет конфигурацию и план действий, не вращает
файл. На сервере должен быть установлен logrotate и включён его timer/cron.
Настройка: еженедельно, восемь архивов, сжатие с задержкой на один цикл. Это
политика ротации, не гарантия точного срока хранения или максимального размера.
Каждый запуск cron заново открывает лог, поэтому copytruncate не нужен.

Вывод renew и nginx дописывается в /var/log/certbot-renew.log. Метки времени
есть у начала, этапов и итога; ошибки содержат этап и код выхода. Успешная
проверка не означает, что сертификат был продлён: он мог ещё не нуждаться в этом.
Успешный reload означает принятие команды; срок сертификата на внешнем HTTPS
позже стоит контролировать отдельно.

Для первоначального получения сертификата в nginx/eazyclass.conf сохранён
закомментированный HTTP-only server. Как и раньше, временно включите его и
закомментируйте остальные server-блоки, затем выполните bootstrap_tls.sh.
После получения сертификата верните HTTPS-блоки и проверьте/reload nginx.
Bootstrap теперь также обновляет cron и logrotate через install_renewal.sh.
Повторно запускать весь bootstrap только ради обновления cron не требуется.
