# Диапазон синхронизации уроков

## Настройка в стандартной админке Celery Beat

Откройте **Periodic tasks**, выберите существующую задачу обновления расписания.
В поле **Task (registered)** должна быть родительская задача:

- `scheduler.tasks.refresh.run_lessons_refresh_pipeline` — сайт;
- `scheduler.tasks.refresh.run_lessons_refresh_by_google_docs` — Google Docs.

В разделе **Arguments** оставьте **Positional arguments** равным `[]`,
а в **Keyword arguments** укажите JSON из таблицы. Сохраните задачу.
Расписание, включение задачи и очередь настраиваются штатными полями Celery Beat.
Дополнительная страница админки и миграции не нужны.

| Период | Keyword arguments |
| --- | --- |
| С сегодняшнего дня, без верхней границы | `{}` |
| С завтрашнего дня, без верхней границы | `{"start_day_offset": 1}` |
| Только сегодня | `{"end_day_offset": 0}` |
| Сегодня и завтра | `{"end_day_offset": 1}` |
| Три дня с сегодняшнего | `{"end_day_offset": 2}` |
| Семь дней с сегодняшнего | `{"end_day_offset": 6}` |
| Семь дней с завтрашнего | `{"start_day_offset": 1, "end_day_offset": 7}` |
| Две недели с сегодняшнего | `{"end_day_offset": 13}` |
| Вчера и сегодня | `{"start_day_offset": -1, "end_day_offset": 0}` |

Оба сдвига отсчитываются от сегодняшнего дня. Обе границы включены.
Количество дней в ограниченном диапазоне: `end_day_offset - start_day_offset + 1`.
Отсутствующий `end_day_offset` или `null` означает отсутствие верхней границы.
Сдвиги должны быть целыми числами (не строками и не `true`/`false`).
Отрицательные значения разрешены для обновления прошлых дней.

Родительские задачи принимают сдвиги. Для разового обновления можно использовать
положительные или отрицательные сдвиги относительно дня запуска.
Конечный сдвиг не может быть меньше начального; равные сдвиги означают один день.
Ошибочная настройка завершает задачу с `ValueError` до запуска парсера и изменения БД,
без бессмысленных повторных попыток. Стандартная форма проверяет JSON,
а смысл параметров проверяется при запуске задачи.

## Поведение пайплайна

Родитель вычисляет даты один раз по часовому поясу Django (`Europe/Moscow`)
и передаёт в задачу парсинга строку `cache_scope`, а в `sync_lessons` — словарь
границ аргументом `_resolved_range`. Оба значения получены из одного диапазона.
В админке родительской задачи их указывать не нужно. Переход через полночь между звеньями
и повторная попытка синхронизации не сдвигают выбранный диапазон.
При следующем ежедневном запуске относительные даты вычисляются заново.

Самостоятельный `scheduler.tasks.synchronisation.sync_lessons` принимает сдвиги
или готовый диапазон, например:

```python
sync_lessons.delay(start_day_offset=1, end_day_offset=7)
sync_lessons.delay(_resolved_range={"start": "2026-09-15", "end": "2026-09-21"})
```

Готовый диапазон нельзя смешивать с ненулевым `start_day_offset` или заданным
`end_day_offset`. В словаре обязательны оба ключа; `end: null` означает отсутствие
верхней границы. Без аргументов обновляются данные с сегодняшнего дня.
При повторной попытке задача передаёт готовые даты, даже если изначально получила сдвиги.
Результат предыдущего звена цепочки приходит в отдельный позиционный аргумент `_`.
Самостоятельная синхронизация использует уже подготовленные данные Redis.
Для регулярного обновления настраивайте диапазон на родительской задаче,
чтобы парсер и синхронизация использовали одинаковый диапазон кеширования.

`LessonsSyncManager` ограничивает создание связанных объектов, добавление,
обновление и удаление уроков выбранным диапазоном и успешно разобранными группами.
Уроки вне диапазона сохраняются. Пустое расписание успешно разобранной группы
удаляет её уроки только внутри диапазона.

Хеши страниц и множества обработанных групп в Redis разделены по конкретным
границам диапазона. Новый диапазон или следующий день не используют отметку
об обработке другого периода. Старые ключи истекают по TTL; вручную чистить
Redis не требуется. Первое обновление нового диапазона заново разбирает страницы.

Параллельные пайплайны по-прежнему используют общие ключи исходных данных Redis:
изоляция одновременных запусков — отдельная задача. Не планируйте пересекающиеся
по времени обновления разных источников/диапазонов.

## Класс диапазона

`scheduler/dtos/lesson_sync_range.py` содержит неизменяемый `LessonSyncRange`:

- конструктор проверяет тип и порядок границ;
- `from_offsets()` вычисляет даты по часовому поясу проекта;
- `to_dict()` и `from_dict()` преобразуют диапазон в JSON-совместимый словарь и обратно;
- `cache_scope` возвращает стабильную метку периода для ключей Redis.

Класс не зависит от имён аргументов Celery. Задача парсинга передаёт пауку только
строку `cache_scope`; эту же метку получает обработчик страницы. При запуске паука
без метки используется диапазон по умолчанию: с сегодняшнего дня без верхней границы.

## Проверка

```powershell
venv/Scripts/python.exe -m pytest scheduler/tests/test_lesson_sync_range.py scheduler/tests/test_lesson_annotation_sync.py --ds=scheduler.tests.sync_settings -q -p no:cacheprovider
```

Тесты используют SQLite в памяти и подмены Redis/Celery; внешние сервисы не нужны.
Исторические миграции scheduler отключены в тестовых настройках из-за ранее
существовавшего переименования отсутствующего индекса.
